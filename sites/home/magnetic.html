Magnetic UI

Magnetic UI

Interfaces that feel a magnet. One small on-device model reads the iPhone's magnetometer and tells your views where the magnet is, whether it is really there, and when it taps the air. Input for any view or library.

Video coming soon
Try the live demo with this page Android only. Install the Magnet Bridge app, tap Start bridge, then connect.

The model

One model reads the magnetometer every frame and answers three things. It is input only: pair it with any view or library.

Magnet.mfxl · v1.0 · 2 MB · MagnetKit

Where the magnet is

  • Reads One magnetometer change, plus the magnet's face and strength when you know them.
  • Answers Position in screen points, height above the glass, and its own uncertainty, over the screen or beside the phone.
  • Tested Real iPhone 15 Pro, median error: 1.2 cm over the screen, 2.0–2.7 cm with the magnet 1.5 cm beside the phone.

Whether it is really there

  • Reads The last 15 s of the field, and whether the phone was overloaded since its last zero.
  • Answers Presence (0–1) and the phone's own offset, so leftovers are cleared and a resting magnet is kept.
  • Tested Real iPhone 15 Pro: a magnet taken away after an overload recognised as gone 96–100 % of the time.

Air taps

  • Reads The last 1.28 s at 50 Hz. In a dip the field barely turns; in a sweep or a flick it does.
  • Answers A tap, about 0.1 s before the hand is back, with where it landed.
  • Tested Real iPhone 15 Pro: 11 of 11 taps over the top half, no false tap in 34 near misses.

Inside: three parts in one file, ~990k weights in half precision, run with Accelerate on every frame.

Built for the phone

Trained on physics, not people

The model learned from simulated magnets only: sizes from a small ring to a large N52 block, every tilt and face, with sensor noise, drift and leftovers. Its simulator is fitted to real recordings. No user data.

On the phone, every frame

A 2 MB model in half precision, run with Accelerate. Nothing to download, no server, no network request.

No permission prompt

The magnetometer is open to every app, so the magnet works the moment the screen appears.

Any magnet

A fridge magnet works; a small neodymium ring works best. iPhone, iOS 17 or newer.

Installation 
// Package.swift, or in Xcode: File › Add Package Dependencies… › paste the URL (Branch: main)
.package(url: "https://github.com/Jakubantalik/Libraries.dev", branch: "main")
// …and in your target's dependencies:
.product(name: "MagnetKit", package: "Libraries.dev")
iOS 17+, iPhone. MagnetKit is a library of its own: the model ships inside it (one 2 MB file) and loads on first use. No other library needed.
Usage 
import SwiftUI
import MagnetKit

// 1. Tell the model about your phone and magnet (once, e.g. in your App's init).
let magnet = MagnetSource.shared
magnet.config.locatorEnabled = true
magnet.config.sensorPosition = CGPoint(x: 70, y: 86)   // the magnetometer, window points
magnet.config.magnetFace = 1                            // north face toward the user
magnet.config.magnetStrength = 6500                     // µT·cm³, optional

// 2. Read it every frame.
struct MagnetDot: View {
    var body: some View {
        TimelineView(.animation) { ctx in
            let r = MagnetSource.shared.reading(now: ctx.date.timeIntervalSinceReferenceDate)
            if let p = r.screenPosition, r.presence > 0.5 {
                Circle().fill(.white).frame(width: 24, height: 24).position(p)
            }
        }
        .ignoresSafeArea()
        .onAppear { MagnetSource.shared.attach() }
        .onDisappear { MagnetSource.shared.detach() }
    }
}

// 3. Air taps, pushes, yanks and swipes.
MagnetSource.shared.addGestureHandler { gesture in
    switch gesture {
    case .tap(let at):         openMenu(at: at)      // at: global points
    case .pullAway(let speed): flingAway(speed)      // cm/s
    case .push, .swipe:        break
    }
}
Pair it with any library 
// A reading is plain values, so anything can follow it:
// a SwiftUI offset, a spring, a shader uniform.
let r = MagnetSource.shared.reading(now: now)
card.offset(x: r.toward.dx * r.pull * 24, y: r.toward.dy * r.pull * 24)

// Metal's liquid rings read it for you:
import MetalFxKit   // brings MagnetKit along
MetalFx(variant: .circle, source: .magnet) {
    Image(systemName: "arrow.right").frame(width: 52, height: 52)
}
Each reading
FieldWhat it is
screenPositionWhere the magnet is, global points (smoothed); nil while the locator is off or unsure.
screenSpread, heightThe locator's 1-σ uncertainty in points, and the height above the glass in cm.
presence0–1, from the presence network. Fade your effect with it; MagnetKit already fades pull.
pull, towardCloseness on a 0–1 log scale and the unit direction from the sensor toward the magnet. Enough for effects without the locator.
distance, approachSpeedRough distance in cm and how fast it is closing in (cm/s, + toward the phone).
tooCloseThe magnet is close enough to the sensor to magnetise the phone. Ask the user to hold it a little farther.
calibratingA new zero is being taken. Show "keep the magnet away".
Gestures
  • .tap(at:) An air tap from the tap network. at is the bottom of the dip, global points, when the locator is on.
  • .push(speed:), .pullAway(speed:) The magnet darted toward the phone or was yanked away, in cm/s, read from how fast ln|B| changes over the last 0.12 s.
  • .swipe(direction:speed:) The located point crossed the screen faster than gestureSwipeSpeed (1,500 pt/s).
Good to know
  • Keep the magnet about 2 cm or more from the sensor. Above ~2,000 µT it magnetises parts of the phone and leaves a 50–250 µT offset for minutes; the kit catches that leftover when the magnet is pulled away, and the presence network clears what remains.
  • Calibration runs on the first attach(), so keep magnets away then. calibrate() re-zeros on demand; MagSafe accessories, steel tables and laptops shift the zero.
  • Beside the phone, a magnet held 2–5 cm above the desk is the reliable case. Resting on the desk, its side and distance are sure but its bearing is not, so deskPrior (on by default) places it beside that edge.
  • Air taps far from the sensor barely change the field: they are missed rather than guessed.
  • The Simulator has no magnetometer: feed MagnetSource.shared.simulatedField from MagnetSimulator.field(magnet:sensor:northUp:) to drive it with a draggable puck.

Android 10+ (minSdk 29), Kotlin. The same model file as on iPhone (assets/Magnet.mfxl) and the same code around it, ported line by line. It reads the uncalibrated magnetometer, so Android's own calibration can't slowly cancel a nearby magnet. Tested on a Pixel 9a through the Magnet Bridge app.
Usage 
import dev.libraries.magnetkit.*

// 1. Tell the model about your phone and magnet (once).
val magnet = MagnetSource.get(context)
magnet.config.locatorEnabled = true
magnet.config.screenSize = Pt(411.0, 923.0)        // the screen, dp
magnet.config.sensorPosition = Pt(205.0, 70.0)     // the magnetometer, dp
magnet.config.magnetFace = 1                       // north face toward the user
magnet.config.magnetStrength = 6500.0              // µT·cm³, optional

// 2. Attach while visible, read it every frame.
override fun onStart() { super.onStart(); magnet.attach() }
override fun onStop() { magnet.detach(); super.onStop() }

Choreographer.getInstance().postFrameCallback(object : Choreographer.FrameCallback {
    override fun doFrame(frameTimeNanos: Long) {
        val r = magnet.reading(frameTimeNanos / 1e9)
        r.screenPosition?.takeIf { r.presence > 0.5 }?.let { p -> moveDot(p.x, p.y) }   // dp
        Choreographer.getInstance().postFrameCallback(this)
    }
})

// 3. Air taps, pushes, yanks and swipes (main thread).
magnet.addGestureListener { g ->
    when (g) {
        is MagnetGesture.Tap -> openMenu(g.at)
        is MagnetGesture.PullAway -> flingAway(g.speed)
        else -> {}
    }
}
On a website Browsers can't read the raw magnetometer, so for the web the Magnet Bridge app runs this model on the phone and serves its answers to pages you approve over ws://127.0.0.1:47613: one JSON frame per reading (position, presence, strength, field) and one per gesture. The live demo on the Preview tab uses it.
Download 
curl -LO https://libraries.dev/downloads/Magnet.mfxl     # 2 MB, model v1.0
One file, three parts: locator (where the magnet is), presence (is it really there) and tap (air taps). Small fully connected networks in half precision; each part's header lists its inputs, outputs and constants.
Run it (Python + NumPy) 
import json, struct
import numpy as np

def read_header(b):
    assert b[:4] == b"MFXL"
    n = struct.unpack("<I", b[4:8])[0]
    return json.loads(b[8:8 + n]), 8 + n

data = open("Magnet.mfxl", "rb").read()
model, start = read_header(data)          # kind "magnet", version, parts

def load(name):
    p = next(p for p in model["parts"] if p["name"] == name)
    b = data[start + p["offset"]: start + p["offset"] + p["length"]]
    head, off = read_header(b)            # inputs, outputs, layers, constants
    layers = []
    for L in head["layers"]:
        n_in, n_out = L["in"], L["out"]
        w = np.frombuffer(b, np.float16, n_in * n_out, off).astype(np.float32).reshape(n_out, n_in)
        off += w.size * 2
        bias = np.frombuffer(b, np.float16, n_out, off).astype(np.float32)
        off += bias.size * 2
        layers.append((w, bias, L.get("act") == "silu"))
    return head, layers

def run(layers, x):
    for w, bias, silu in layers:
        x = w @ x + bias
        if silu:
            x = x / (1 + np.exp(-x))      # SiLU
    return x

# Where the magnet is, from one field change (µT, device axes).
head, locator = load("locator")
def locate(b, strength=None, face=None):
    b = np.asarray(b, np.float32)
    nb = np.linalg.norm(b)
    u = b / nb
    if face is not None: u = u * face
    elif u[2] < 0: u = -u
    x = np.array([u[0], u[1], u[2],
                  (np.log(nb) - head["logbMid"]) / 2,
                  (np.log(strength) - head["logkMid"]) / 1.5 if strength else 0,
                  1.0 if strength else 0.0, 1.0 if face is not None else 0.0], np.float32)
    y = run(locator, x)
    d = y[:3] / np.linalg.norm(y[:3])
    r = np.exp(y[3] + head["logrMid"])    # cm
    return d * r                          # magnet relative to the sensor, cm

# A magnet 2 cm right, 3 cm below and 1.5 cm above the sensor, north face up:
print(locate([64.4, -96.6, -60.8], strength=6500, face=1))   # ≈ [1.94, -3.02, 1.58]
The file
  • Magnet.mfxl "MFXL", a little-endian UInt32 header length, a JSON header (kind "magnet", version, parts with offsets and lengths), then each part as a complete MFXL file of its own.
  • part The same layout, its header listing layers (in, out, act), then each layer's weights (out × in, row-major) and biases as float16. Activation SiLU, none on the last layer.
  • locator 7 inputs (field direction, log strength, magnet strength and face when known) → 6 outputs: direction, log distance and its uncertainty. Device axes: x right, y toward the top edge, z out of the screen; cm from the magnetometer.
  • presence The last 15 s of the field (1.28 s at 50 Hz in detail, a 10 Hz magnitude history, the overload peak) → presence logit and the phone's own offset.
  • tap The last 1.28 s at 50 Hz → "a tap just finished" logit.
The exact presence and tap inputs are in each part's header and in MagnetKit's MagnetPresence and MagnetTap (Swift and Kotlin). Trained only on simulated magnet physics, its simulator fitted to real iPhone 15 Pro recordings. 
Add MagnetKit from Libraries.dev to my SwiftUI app: views that react to a
magnet near the iPhone, using its on-device magnet model.

Install (Swift Package Manager, iOS 17+):
.package(url: "https://github.com/Jakubantalik/Libraries.dev", branch: "main")
.product(name: "MagnetKit", package: "Libraries.dev")

Setup (once):
import MagnetKit
let magnet = MagnetSource.shared
magnet.config.locatorEnabled = true
magnet.config.sensorPosition = CGPoint(x: 70, y: 86)   // magnetometer spot, window points (iPhone 15 Pro)
magnet.config.magnetFace = 1                            // +1 north toward the user, -1 south
magnet.config.magnetStrength = 6500                     // µT·cm³, optional
MagnetSource.shared.attach()   // on appear; detach() on disappear

Every frame (inside a TimelineView(.animation)):
let r = MagnetSource.shared.reading(now: ctx.date.timeIntervalSinceReferenceDate)
- r.screenPosition: CGPoint?: the magnet, global points (locator on)
- r.screenSpread, r.height: uncertainty (pt) and height above the glass (cm)
- r.presence: 0-1: is a magnet really there
- r.pull (0-1), r.toward (unit vector from the sensor): work without the locator
- r.distance (cm), r.approachSpeed (cm/s), r.tooClose, r.calibrating

Gestures:
MagnetSource.shared.addGestureHandler { g in
    switch g {
    case .tap(let at): break          // air tap: magnet dipped toward the glass and back
    case .pullAway(let speed): break  // yanked away, cm/s
    case .push(let speed): break      // darted toward the phone, cm/s
    case .swipe(let dir, let speed): break
    }
}

The model (MagnetModel, Magnet.mfxl v1.0, 2 MB, bundled; trained on simulated
magnet physics, run on device with Accelerate, no permission prompt) answers
where the magnet is, whether it is really there, and air taps.
Config: locatorMode .network (default) or .dipole (physics; needs magnetFace),
deskPrior, presenceModel, tapModel, gestureSwipeSpeed.

Pairs with any library: a reading is plain values. With MetalFxKit,
MetalFx(variant: .circle, source: .magnet) bends liquid-metal rings toward it.

Keep the magnet 2 cm+ from the sensor (r.tooClose), calibrate with no magnet
near, and in the Simulator feed MagnetSource.shared.simulatedField from
MagnetSimulator.field(magnet:sensor:northUp:).
